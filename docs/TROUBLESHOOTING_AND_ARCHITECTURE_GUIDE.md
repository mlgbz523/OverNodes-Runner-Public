## 第一章：网络拓扑底层认知

### 1.1 灵魂拷问：可以直接拿代理 IP 上网吗？优选 IP 是不是没有意义了？
**核心结论：两者是“火箭助推器（进站）”与“在轨作业卫星（出站）”的关系，缺一不可。直接裸连代理 IP 必死无疑。**

```
【完整健康链路】
你的电脑 ──(1. Anycast 优选BGP专线)──> Cloudflare 亚太边缘 ──(2. CF全球私有骨干网)──> 落地机房 ──(3. SOCKS5)──> 目标网站
           [0% 丢包 / sub-120ms]                      [内网专线极速传输]                 [消除1034 / 解锁流媒体]
```

#### 为什么直接裸连海外代理 IP 无法上网？
1. **第一公里不可抗力**：国内三大运营商（电信/联通/移动）到海外普通机房公网没有 BGP 优化，晚高峰国际出口丢包率高达 **40% ~ 70%**，延迟飙升至 300ms+。
2. **GFW 特征瞬秒**：SOCKS5 是明文/弱加密协议，直连跨国会暴露清晰的握手特征，GFW 的 DPI 检测会在数分钟内向该 IP 发送 TCP Reset，直接将端口打入黑洞。
3. **职责划分**：
   * **优选 IP (Inbound)**：负责**抗审查、抗 QoS 限速、跨海超低延迟进站**。目标网站永远看不到它。
   * **代理 IP (Outbound)**：负责**洗白机房属性、规避 Cloudflare 内部 Error 1034 同网回源死循环报错、解锁流媒体**。

## 第二章：干净测试环境与零追踪诊断体系建设

在排障与节点验收时，依赖第三方测速网页常伴随广告植入、数据收集与跨域拦截。

### 2.1 诊断工具矩阵交付
本工程沉淀了两套本地纯净排障套件：
1. **CLI 终端深度诊断引擎**：[`tools/node_diagnose.py`](../tools/node_diagnose.py)
   * 零外部依赖，直接走指定本地代理端口（如 `http://127.0.0.1:11451`）；
   * 输出 Cloudflare 官方 `cdn-cgi/trace`（真实 IP、Colo 边缘机房代码如 LAX/SJC、TLS 版本、WARP 状态）；
   * 输出全球权威业务连通性与 RTT 延迟矩阵（Google、YouTube、GitHub、Cloudflare、Oracle 官网）。
2. **原生 Web 零追踪仪表盘**：[`tools/node_checker.html`](../tools/node_checker.html)
   * 采用现代 Dark Glassmorphism 纯前端架构，双击即可在浏览器本地运行；
   * **CORS 跨域破局**：前端调用 `https://one.one.one.one/cdn-cgi/trace`（Cloudflare 官方原生自带 `Access-Control-Allow-Origin: *`）规避浏览器拦截；
   * 联动 `https://ipwho.is/` 免鉴权高精度解析真实出口 ASN 与物理归属；
   * 内置原生 **WebRTC 穿透泄漏探针**，检测真实内网/公网 IP 是否遭浏览器外泄。

## 第三章：Clash 测速失真与混合订阅“劣币逐良币”事故复盘

### 3.1 事故现象
将 `[直出]` 节点与 `[socks5]` 链式节点打包进同一订阅后，Clash 的自动优选组全部被直出节点霸占，出口 IP 频繁变回 Cloudflare WARP（`104.28.x.x`），再次遭遇 **Error 1034 环路拦截**，精心筛选的 20Mbps+ SOCKS5 代理完全被架空。

### 3.2 底层根因（Goodhart's Law 指标失真）
* **物理链路差异**：
  * `[直出]` 链路只有 1 跳（`电脑 -> CF边缘 -> 目标网站`），测速耗时仅 100~130ms；
  * `[socks5]` 链式链路有 2 跳（`电脑 -> CF边缘 -> SOCKS5 落地 -> 目标网站`），多了一次 SOCKS5 握手，测速耗时在 200~250ms。
* **Clash 机制缺陷**：`url-test` 策略组**只看延迟数字大小**，无脑将 100% 通用流量导向表面延迟更低的直出节点，导致系统级劣化。

### 3.3 架构治理方案
在 [`ACL4SSR_Custom_Advanced.ini`](../ACL4SSR_Custom_Advanced.ini) 中推行**主次物理隔离**：
```ini
; 主力自动优选组：严格限定为 SOCKS5 链式节点，彻底剔除直出
custom_proxy_group=⚡ 自动优选`url-test`(?i).*(socks5|链式).*`http://cp.cloudflare.com/generate_204`300,50,50

; 直出节点单独封装为特种旁路，仅供特定白名单业务（如 Oracle）调用
custom_proxy_group=🏛️ 特种直出专线`url-test`(?i).*(直出|纯净).*`http://cp.cloudflare.com/generate_204`300,50,50
```

> **治理戒律**：下游规则集若强引用标准策略组名（如 `rules[76] ooklaserver.net -> ⚡ 自动优选`），**切勿更改组名，而应在其内部匹配正则上收紧准入条件**。

## 第四章：订阅转换器正则失配与 DIRECT 裸奔灾难

### 4.1 事故现象
配置更新后，谷歌应用商店图片全裂、插件下载失败转圈。Clash 面板中 `🇸🇬 新加坡节点`、`🇺🇸 美国节点`、`🇩🇪 德国节点` 内部**只有一个 `DIRECT`**，全员失配。

### 4.2 根因分析
* **节点命名真实结构**：`US-443-01-[socks5]-...`（国家代码在前，`socks5` 标识在后）；
* **错误正则**：`(?i)(socks5|链式).*(US)`（强行要求 socks5 必须在国家代码之前）；
* **雪崩链路**：正则失配 -> 分组节点数为 0 -> 订阅转换器自动降级塞入 `DIRECT` -> 依赖国家组的国外媒体/Google 下载全走国内宽带直连 -> 遭 GFW 阻断报废。

### 4.3 终极修复与容灾底座 (`Fail-safe`)
1. **前后拓扑兼容正则**：
   ```ini
   custom_proxy_group=🇺🇸 美国节点`url-test`[]⚡ 自动优选`(?i).*(🇺🇸|美国|US|USA|美西|美东).*(socks5|链式).*`http://cp.cloudflare.com/generate_204`300,50,50
   ```
2. **强制前置容灾成员**：在所有国家组中挂载 `[]⚡ 自动优选`。即便该地区节点临时全挂，也会平滑回退至 SOCKS5 全局优选，**物理级杜绝节点组落入 DIRECT 裸连**。

## 第五章：Steam 客户端生态阻断、证书伪造与 -100/-200 根治

### 5.1 事故现象
访问 Steam 社区/饰品市场报错：
* `Invalid SSL Certificate: The SSL certificate for https://steamcommunity.com/market/ is invalid (error:-200 status:1)`；
* 随后退化至 `http://error/` 显示 `错误代码：-100 服务器连接失败`；
* Clash Verge 连接监控搜索 `steam` 显示 **【空空如也】**。

### 5.2 根因排查
1. **Steam 客户端架构特性**：Steam 主程序（Win32）与内嵌 CEF 网页引擎**默认完全不遵守 Windows 系统代理（System Proxy）**。
2. **流量脱靶直连**：流量未进代理，直接从物理网卡直连国内宽带，撞上 GFW 的针对性 SNI 阻断与伪造证书，CEF 校验失败中断连接。

### 5.3 解决办法
* **解法 A（全局接管）**：在 Clash Verge 中开启 **TUN 模式 (TUN Mode)**（安装服务驱动），虚拟网卡在操作系统驱动层拦截 Steam 所有数据包。
* **解法 B（启动参数指定）**：在 Steam 桌面快捷方式的目标末尾追加 Chromium 级网络代理参数：
  ```cmd
  "F:\APP\steam\steam.exe" -http_proxy=http://127.0.0.1:11451 -proxy-server="http://127.0.0.1:11451" -tcp
  ```

## 第六章：Steam 429 频控封锁与登录二维码转圈深水区攻坚

### 6.1 事故现象
1. 市场虽然能打开，但网页版社区提示：**“您最近作出的请求太多了。请稍后再重试您的请求。”**（客户端对应抛出错误码 `-118` 与 `-113`）。
2. Steam 登录界面的手机扫码登录二维码**在原地无限转圈刷新，始终无法生成**。
3. Proxifier 监控中 `steamwebhelper.exe` 显示：**发送 1.75KB，接收 0 字节 (`0 bytes received`)**。

### 6.2 根因三连击与逐层破局

#### 根因 1：公共 SOCKS5 节点的并发爬虫污染（HTTP 429）
* **真相**：`107.167.18.x` 这类公共代理池有海量倒卖饰品脚本和爬虫机器人共用，触发了 Valve 的单 IP 速率限制（Rate Limit）。
* **破局**：在规则中建立独立的 `🎮 Steam服务` 策略组，**将默认首选设为 `🏛️ 特种直出专线`（Cloudflare 官方纯净出口）**。直出出口拥有数以千计的动态 IP 且无机器人爬虫共用，429 频控立刻解除。

#### 根因 2：登录与二维码鉴权 API 被误划入直连
* **真相**：登录界面的二维码必须实时向 `*.login.steampowered.com` 和 `*.api.steampowered.com` 建立长连接。此前的规则将 `steampowered.com` 当作游戏下载放进了“🎯 全球直连”，导致这两个核心 API 直连国内宽带遭遇阻断。
* **破局**：在规则中将鉴权 API 强行截留收归 `🎮 Steam服务` 代理：
  ```ini
  ruleset=🎮 Steam服务,[]DOMAIN,login.steampowered.com
  ruleset=🎮 Steam服务,[]DOMAIN,api.steampowered.com
  ruleset=🎮 Steam服务,[]DOMAIN-SUFFIX,login.steampowered.com
  ruleset=🎮 Steam服务,[]DOMAIN-SUFFIX,api.steampowered.com
  ruleset=🎮 Steam服务,[]DOMAIN-SUFFIX,steamcommunity.com
  ruleset=🎮 Steam服务,[]DOMAIN-SUFFIX,steamstatic.com
  ruleset=🎯 全球直连,[]DOMAIN-SUFFIX,store.steampowered.com
  ruleset=🎯 全球直连,[]DOMAIN-SUFFIX,steamcontent.com
  ```

#### 根因 3：Proxifier 本地 DNS 投毒（假 IP 黑洞）
* **真相**：Proxifier 发出 1.75KB 接收 0 字节，且目标 IP 解析为奇怪的 `88.191.x.x`。原因是 Proxifier 默认在本机由国内宽带解析 DNS，拿到污染毒 IP 后发给代理，连接直接超时。
* **破局**：在 Proxifier 中进入 **Profile -> Name Resolution**，必须勾选 **`Resolve hostnames through proxy`（通过代理服务器解析域名）**，彻底切断本地 DNS 污染。

## 第七章：全链路排障万能排查军规

遇网络异常、应用报错、网页转圈时，严格按此 5 步定位：

```text
┌────────────────────────────────────────────────────────────────────────┐
│                        全链路排障五步定位法                            │
├────────────────────────────────────────────────────────────────────────┤
│ 1. 看连接流量 (Clash 连接面板 / Proxifier)                             │
│    - 搜索目标进程/域名：有连接吗？                                     │
│    - 如果【空空如也】：说明软件根本没走代理（需开 TUN 模式或设命令行代理）│
│    - 如果【接收字节为 0】：说明死于本地 DNS 投毒（需开启远程 DNS 解析）   │
├────────────────────────────────────────────────────────────────────────┤
│ 2. 看路由命中 (Rule Match)                                             │
│    - 命中了哪个策略组？是否落入 `🎯 全球直连` 或 `🐟 漏网之鱼`？        │
│    - 核心业务域名、静态 CDN（如 fastly/akamaihd）是否被粗暴直连拦截？ │
├────────────────────────────────────────────────────────────────────────┤
│ 3. 看 HTTP 状态码                                                      │
│    - 403 Forbidden：落地 IP 被目标 WAF（如 Akamai/Cloudflare）拉黑      │
│    - 429 Too Many Requests：共享代理节点被爬虫刷爆（立即换直出/换国）  │
│    - 1034 Error：Cloudflare Worker 直出撞上同网源站（必须走 SOCKS5）   │
├────────────────────────────────────────────────────────────────────────┤
│ 4. 看测速与吞吐匹配                                                    │
│    - 视频卡顿 / 单线程网盘慢：受单 TCP 窗口与 SOCKS5 上限限制          │
│    - 解法：多线程接管工具（Chrono / IDM）+ 大流量走直出或负载均衡聚合   │
├────────────────────────────────────────────────────────────────────────┤
│ 5. 看客户端缓存机制                                                    │
│    - 规则生效后客户端仍报错：清理 CEF / 浏览器旧数据，彻底重启进程     │
└────────────────────────────────────────────────────────────────────────┘
```
